## Decisions the PM made
- **Recovery storage layout:** one `.entry` envelope per folder and page. It is a saved-format change confined to the recovery folder, approved through `next.md`'s R-10 and R-5. The envelope was chosen over a manifest because it needs no generation cleanup and leaves `<id>.assets` (0098) untouched.
- **R-4 marker:** the kept `<id>.assets` folder itself is the retry marker, and the entry is retired once its page lands. This follows the review that showed whole-entry re-replay isn't idempotent.
- **R-3 path:** the closed-page path shares the rule gate, the merge and the reread-and-retry loop with the open page, but not `_checkFile`, which mutates open-page state. The reviewer judged that no gap remains.
- **Supersede rule:** a recovery copy is deleted only for an identical, or strictly later, entry of the same folder and page.
- **Formula limits:** tree height 256 and parentheses 100, with a flat run as one node. A formula past the limits is `#ERROR!` on every platform.
- **Cleanup ownership:** a live bash, sh, PowerShell, pwsh or `cmd /k` owns its tree. Known gap: a Git Bash `flutter` script process that outlives its Claude Code shell is kept, and reported as owned; end that bash by hand.
- **Release with the MCP server running:** the running exe was moved aside, not stopped.
- **Worktrees** were created from `origin/main`, not the local main, so section 3 branches were rebased onto local main before merging.
- **The `_isOpenFile` safety net** is kept as defensive code.
- **Not done:** streamed hashing (it needs a direct `crypto` dependency in the app) and an exclusive save in `noted_core` (scope).
