# Run 2026-11-01-02: AI access redesign, settings panel, follow-ups

## Summary
AI access now has two parts. AI boxes own their rules through per-box Writer and Reader codes, with new-connection approval, optional ask-before-each-write, an activity log and expiry. Pages and binders are Open, Privileged (Reader codes) or Guarded, Guarded by default, and pages can only tighten. Code checks go through the running app over `ai-link/2`, and `noted_mcp` 0.3.0 reads saved files only. A shared Page and Binder settings panel replaces the settings entries in the right-click menus, and box types can be disallowed per page or binder. The follow-ups from the last report are done. All tests and the 50-case integration suite pass. CI is green on the code. The release exe and zip are rebuilt, and `noted_mcp` is re-registered with Claude Code without a token.

## Decisions the PM made
- **No Box API change.**
  - The host stops calling `BoxCodec.aiOwner`, and `AiWrite.connectionId` carries the Writer code's id.
  - App services reach the AI box through `AiModule(access: AiBoxAccess)`.
  - One builder's new `CanvasController.isDisposed` was removed rather than added.
  - **Host-only additions** are recorded in `BOX_API_CHANGELOG.md` with no version bump: `PageCanvas.disallowedTypes`, `ModuleRegistry.isSwitchable`, `moduleForFile(exclude:)`, `convertPageAttachments(skipTypes:)` and `showConflictDialog(disallowedTypes:)`.
- **No new dependencies or packages.**
- **Grants, not content:** for a read, the app answers with page or box ids, and `noted_mcp` renders from saved files. That keeps one renderer and keeps the live screen out (invariant 4).
- **Storage:**
  - `ai-access.json` and `ai-activity.json` in `%APPDATA%\Noted`, local and never synced.
  - Per-box *Ask before each write* lives there too, not in the page file.
  - The log is capped at 1000 entries.
- **Top of the chain:**
  - A top-level standalone page whose header records no parent may choose any access value. Otherwise standalone pages could never be Open or Privileged.
  - A page whose recorded parent can't be read starts from Guarded.
- **Timings and limits:**
  - Approval questions: 45 s.
  - Request deadline: 50 s, below the MCP client's 55 s timeout.
  - The pause after a Deny: 30 s.
  - Waiting questions: one per code, four in all.
- **Expiry choices:** none, 1, 7 or 30 days.
- **Box ids are unique per page:** a box code's target records the page id at issue, and `read_box` takes an optional `page_id`.
- **The MCP still reads boxes of a disallowed type:** `boxTypes` controls inserting and editing, not confidentiality.
- **Code and HTML in AI writes:** one plain paragraph per block, with its lines kept.
- **Revoke, session revoke and the Ask switch** stay usable on a read-only page, since they change only the local store.
- **Build for screenshots:** the maintainer's Noted was running from the release folder, so reviewer-ui used a release build made in a separate worktree. The final package waited until that Noted was closed.

## Needs the maintainer
1. **Letting `noted_mcp` verify codes itself (SHA-256 only)**, so code-based reads work with Noted closed.
   - Options:
     - (a) keep checks in the app only, as built;
     - (b) allow hashing in the server and let it read `ai-access.json` for reads only;
     - (c) as (b), but only for sessions already approved, which needs approvals keyed by something more stable than the per-process session id.
   - Note on (b): new-session approval, ask-before-write and the activity log need the app, so reads with Noted closed would skip approval and logging.
   - Recommendation: **(a)** for now. Every new `noted_mcp` process is a new session, so (b) would bypass approval exactly when the user isn't there. Revisit with (c) if offline reads matter.
2. **Invariant 4's wording in CLAUDE.md** still says the app accepts a write "only for a box owned by the requesting AI's token, on a page whose AI setting allows writing".
   - Suggested wording: "only for a box whose Writer code the request carries, from a session the user approved, and saves it through its normal path".
   - I didn't change an invariant without your sign-off.
3. **Existing pages may lose AI access.** The old Whole page migrates to Open, but under tightening-only inheritance a page set to Whole page inside a binder or parent with no value (now Guarded) becomes Guarded.
   - Options:
     - (a) leave it, and the user re-opens access at the binder or parent;
     - (b) show a one-time note listing affected pages;
     - (c) on first run, migrate such a page's Open up to its binder.
   - Recommendation: **(a)**. Guarded is the safe failure, and (c) would widen access the user didn't set at that level.
4. **Standalone pages** (outside any binder) take their top from the top-level page, a PM reading of section 2.
   - Alternative: a *Pages* section setting in the gear menu acting like a binder.
   - Recommendation: keep it as built.
5. **0035 and conflict choices** for boxes the device can't run, or whose type is disallowed: the dialog lets the user keep one version or both, without an editor. 0035 says the conflict stays until a supporting device resolves it.
   - Options:
     - (a) curate 0035 to allow choosing a whole version;
     - (b) hide the choices.
   - Recommendation: **(a)**. Choosing a whole saved version never parses the data.
6. **Old AI connections in `settings.json`.** The `aiConnections` value, including the "Claude Code" connection from the last run, is kept as written and unused.
   - Options:
     - (a) leave it;
     - (b) remove it on the next settings save.
   - Recommendation: **(b)** in a later run. It holds only hashes, but it is dead data.
7. **Single-instance guard on macOS and Linux:** Windows only. macOS needs a check in `AppDelegate` when the binary is run directly; on Linux the GTK runner needs `activate` to present the existing window.
   - Recommendation: do this with the Apple build path.
8. **reviewer-ui polish left** (see Reviews). Recommendation: one small UI task in the next run.
