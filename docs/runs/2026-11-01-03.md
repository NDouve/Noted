# Run 2026-11-01-03: AI access while Noted is closed

## Summary
An AI can now reach its codes while Noted is closed.
- **Reads:** `noted_mcp` 0.4.0 checks approved codes itself, by SHA-256 hash against the saved code store, and logs what it does to its own append-only file.
- **Writes:** it writes an AI box's own data into the page file, but only for a box whose new **Allow writes while Noted is closed** switch is on, and only within the box's new **Writer permission** (Append only by default, Edit, Full).
- **Approval** is now per code, and a code first used while Noted is closed is asked about when Noted next opens.
- **Detecting a running Noted:** Noted holds an OS lock while it runs, so the server never writes behind a running app.
- **Changes:** invariant 4 has its approved new wording; there is a one-time note for pages that lost AI access; the follow-ups are done.
- **Status:** all tests and the 50-case integration suite pass, and CI is green. The release exe and zip are rebuilt, and `noted_mcp` is re-registered with Claude Code.

## Reviews
Every diff went to `reviewer`. The visible changes also went to `reviewer-ui`.

**Blocking findings, all resolved:**
- **Core importer:**
  - package:markdown was super-linear. 64 KB of `_a` took 62 s, and deep nesting overflowed the stack. Fixed with per-block caps, plus a whole-import budget after a later near-cap case took 19 s/MiB. Hostile 1 MB inputs now take under 0.8 s.
  - The app mapped `replace_ai` with `byName` and crashed. It now maps the modes explicitly.
- **noted_mcp:**
  - It decided "closed" whenever the link didn't answer, so it could write under a running app. An AI's parallel calls could trigger that by filling the link. It now relies on positive signals only: the app's OS lock or the link greeting.
  - Parallel closed writes in one process shared a temp name, which could give a false success and lose a write. Writes are now serialized, with exclusive random temp files.
  - The box-type and page-code rules ignored parents in other standalone folders. They now use one tree.
- **App:**
  - The running lock was tried once and failures were silent. It now retries, opens without truncating, and shows a banner.
  - The log trim emptied the file before rewriting it, so a crash could lose the log. It now overwrites in place, then shortens.
- **Task P:**
  - The access-loss note could write over an unreadable `settings.json` at startup. It now never writes then.
- **Others:**
  - The splice could pick a different record than the app for a duplicate id.
  - AI dividers piled up under `replace_ai`.

**Non-blocking findings fixed** (the main ones):
- **noted_mcp:**
  - The log append writes at the current end, and retries only on real lock violations.
  - The damaged-store and missing-store messages are separate, and a box without the closed-app switch gets a clear message.
  - The invariant test also catches `create`, `copy`, `createTemp` and `Isolate.*`.
  - Lock tests hold the lock from a separate process.
- **App:**
  - Startup approvals are capped, and a live request joining one waits only for its own deadline.
  - Merged log entries are limited to known codes, cleaned, and shown with the code's current label.
  - The lock is also kept in a top-level variable.
- **AI box:**
  - Ask-before-write turns the closed-app switch off.
  - An expired code shows only "Expired".
  - The warning and Edit-note wording is clearer.
  - Radio semantics are merged onto the tappable node.
- **P:**
  - The note isn't marked shown while a binder is unreadable, and its rows stay live.
  - Pinning is restored, and the focus-ring test is now meaningful.

**Non-blocking findings left:**
- **Copied or formatted AI marks.** Under Edit, `replace_ai` deletes any block whose AI mark still matches, including one the user bolded or ticked, and an AI block the user pasted elsewhere (0104's fingerprint semantics). The panel says so.
- **Two server processes** writing the same page at the same instant can still lose one write (compare-then-rename). Each process serializes its own writes. This is documented in `docs/mcp.md`.
- **Revoked codes** drop their closed-app entries from the activity list, while in-app entries stay. Entries for unknown codes can't be told apart from forged ones.
- **Box ids are unique per page only.** A box code whose page lost the box can reach a same-id box on a copied page. The app does the same, and this predates this run.
- **CI runs tests on Windows only**, so the cross-process lock tests aren't exercised on Linux or macOS.
- **reviewer-ui:**
  - The AI connections panel scrolls with no cue.
  - Background chips look disabled when Page settings is opened from the note for a page that isn't open.
  - *Page settings* in the note reads like plain text.
  - Deny's default-focus cue is faint in light.
  - A Reader prompt names the code's label ("wants to read Research reader").
  - The Contextual More menu overlaps the bar by about 10 px.
- **Not verified by reviewer-ui:** keyboard focus outlines and scrolling to the end, because synthetic input didn't drive them. The lock banner text it captured is the earlier wording; 1dc72bd made it accurate (below).

## Decisions the PM made
- **Asked the maintainer, who approved:** the `markdown` 7.3.1 dependency (BSD-3-Clause, Dart team, exact pin, direct in noted_core) and **Box API 0.10** (`AiWriteMode.replaceAiText`, additive, in `BOX_API_CHANGELOG.md`).
- **Settings kept locally in `ai-access.json`**, not synced: the Writer permission and the closed-app switch are per box there, beside `askBeforeWrite`.
- **Running detection:**
  - The app holds an exclusive lock on `noted-running.lock` for its life.
  - The server counts Noted as running if that lock is held or `ai-link.json` greets. While Noted is running but not answering, the server answers "Noted is running but didn't answer; try again." and never writes.
- **Edit semantics:** `replace_ai` replaces every block whose AI mark still matches, at the position of the first such run, and keeps user blocks in place.
- **Full** permission includes `replace`, and replacing with empty content empties the box.
- **The server log** holds code ids only, never keys. The app shows closed-app entries only for codes it still knows, and trims the log to its last 1000 lines.
- **Pending approvals** are asked at most once per pending use. The answer time is stored as `pendingAnswered` in the code's extra fields.
- **The banner text:** "Noted couldn't take its running lock and keeps trying. If its AI link isn't working either, AI tools may treat Noted as closed and write to boxes that allow writes while Noted is closed."
- **`revokeSession`** is deprecated on `AiBoxAccess` (the module's own interface, not the Box API) rather than removed.
- **A local untracked `AGENTS.md`**, which differed from the one the maintainer committed upstream (7e11096), was renamed to `AGENTS.md.untracked-backup` so main could be rebased onto the upstream commit. Nothing was deleted. `.codex/` was left untouched.

## Needs the maintainer
1. **Revoked codes in the activity list.** Revoking a code hides its closed-app log entries but not its in-app ones.
   - Options:
     - (a) keep it;
     - (b) keep a revoked code's id and label in the store as revoked, so its history stays and forged entries for unknown codes are still dropped.
   - Recommendation: **(b)**, as a small next task.
2. **Two server processes, one page.** Should closed-app writes take a per-folder lock file around compare-and-rename? That widens the narrow writer's file allowlist under invariant 4.
   - Options:
     - (a) leave it documented as is;
     - (b) add `.noted_mcp.lock` per folder.
   - Recommendation: **(a)** unless several AI apps write the same box while Noted is closed.
3. **CI on Linux and macOS.** The workflow tests on Windows only. Recommendation: add a Linux test job, so file-lock behaviour is checked where locks are per process.
4. **reviewer-ui polish left** (see Reviews). Recommendation: one small UI task next run, starting with the connections panel's scroll cue and the Reader prompt naming the box.
5. **Stray test processes.** Earlier test runs left `flutter_tester`/`dart` processes, which a builder couldn't stop. They may hold leftover worktree folders under `.claude\worktrees\`, which couldn't be removed.
   - Recommendation: end them in Task Manager and delete the leftover folders.

## Hand checks
1. Start Noted from `app\build\windows\x64\runner\Release\noted.exe`. If any page had the old "Whole page" setting and is now Guarded or Privileged by inheritance, the "Some pages are no longer open to AI" note appears once.
2. Restart Claude Code, so it starts the re-registered server. In an AI box, *Connect a chat* → *Writer*, and give Claude Code the code. Ask it to `write_box` with `mode: "append"`.
   - Noted asks once: "… wants to read and write …".
   - Allow. Later writes don't ask again.
3. Open the box's connections panel.
   - The code reads "Approved <date>".
   - Writer permission is *Append only*. Ask for `mode: "replace"`: it is refused with the Writer-permission message.
4. Turn on *Allow writes while Noted is closed*. Close Noted and ask Claude Code to append.
   - It answers "Written to box …".
   - Reopen Noted: the text is in the box, and the box's Activity shows the write "while Noted was closed".
5. With the switch off and Noted closed, ask for a write. It is refused with "This box doesn't take writes while Noted is closed…", and the page doesn't change.
6. Issue a new Reader code and use it for the first time with Noted closed.
   - The AI is told "Approve this code in Noted first…".
   - When Noted opens, it asks about that code ("It asked while Noted was closed").
7. Turn on *Ask before each write*. The closed-app switch turns off and greys out.
8. Check CI on the final push: <https://github.com/NDouve/Noted/actions>.
